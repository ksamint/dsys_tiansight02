# 侍天 TIANSIGHT 报告模板手册 v1.1

> 用途：今后所有面向客户的分析报告、补充报告、提案附件，都按本手册制作，保证看起来出自同一家公司、读起来同一种口径、交付物同一套结构。
> 依据：侍天 TIANSIGHT 设计系统（组织默认，v0.7 规则）、侍天菜单分析方法论 v3.0、侍天餐饮模型；以及三份客户成稿（提案、对标补充报告、差评诊断）的复盘。
> 配套：模板幻灯片 `deliverables/report-template/`（规范页 + 二十七种页型样张 + 可跳转 PDF）、制作工具包 `templates/report-kit/`（页型函数库 `tsk` + 生成、检查、导出流水线）、技能 `skills/ts-slides-report/`。
> 与 `skills/ts-html-report`（1280×720 HTML 报告）的分工：本手册管 1920×1080 的 Claude Slides 幻灯片报告与其 PDF。

---

## 一、总原则（五条，按优先级）

1. **结论先行，证据随行。** 论证页标题是一句结论；数据页、对比页、附录可用名词短标题（见第二节）；每个数字带单位、时间窗与来源；推算与设计的数一律标明读数身份。
2. **参谋，不是销售。** 沉稳、克制、敢言；不替老板拍板，不把预期写成已发生的结果。
3. **素墨为纸，玄墨为字，土金为骨。** 淡墨纸与宣纸为底，玄墨写字，土金画线；朱红只做印记与警示，单页 ≤ 5%。
4. **一页一事。** 一页只讲一个判断；放不下就拆页，不缩字。
5. **可复核、不缺项。** 每个数字能追到计算结果文件或公开来源；生成前列出应有的门店、图、明细与品项数量，生成后逐项核对；精简文字不得删数据或页面；所有页面过渲染检查，所有链接可跳转。

## 二、品牌声音

| 规则 | 宜 | 忌 |
|---|---|---|
| 论证页标题是结论句，句号结尾 | 「目标菜品评论提及率门店 A 为 62%，其余门店均低于 10%。」 | 「菜品评论分析」 |
| 数据页、对比页、附录用名词短标题，不加句号；关键数值写进正文 | 「字段说明」「门店对比」「四象限」 | 「下面我们来看一下各门店的对比情况。」 |
| 客户明确要求短标题时，整份报告用短标题；论证结论移到正文首句或提示条 | 标题「门店对比」，提示条「A 店复购点击率最高，为 20.7%」 | 为凑结论句删去数据 |
| 正文保留关键数值，删口语化解释和重复背景 | 「9 店中 3 店低于均值」 | 「从图中可以看出，大家可以发现…」 |
| 主语是门店、菜单、顾客 | 「门店是否…」「顾客是否…」 | 「我们认为…」（不用「我们」「您」） |
| 第三人称称侍天 | 「侍天把这两件事放在同一张经营蓝图里」 | 「我们为您赋能」 |
| 每个建议带依据、动作、验证 | 「出炉到上桌 ≤ 15 分钟，用 POS 时间戳验收」 | 「提升出品效率」 |
| 设计值、推算值明说 | 「设计假设值，须经门店测试确认」 | 把目标写成已实现 |
| 数字带单位与窗口 | 「7–9 月 1,209 条」 | 「大量差评」 |

**词表**

| 优先 | 避免 |
|---|---|
| 领航、校准、复盘、验收、增利 | 赋能、抓手、闭环、打法、解决方案 |
| 模型、体系、规格、口径 | 颠覆、爆款、裂变、包治百病 |
| 数据校准 | 数据补全 |

统计引用中的「同比增长」可照原文保留；侍天自己的主张用「增利」。

**标点与符号**：中文用全角标点；「·」作连接（开店之前 · 把生意想清楚）；「、」分隔句内并列；中文句中不用「—」。不用 emoji，不用感叹号（顾客原话除外）。

**任何文字不小于 24px。** 字标 TIANSIGHT 双色：T、A 为玄墨 700，INSIGHT 为金 400，不得单色。

### 3.3 版式

- 画布 1920 × 1080；左右边距 128px，上 128px；有页脚的页下边距 160px，正文不越过 y = 920。
- 页头固定结构：**眉题 → 结论标题 → 右侧标签胶囊 → 土金 2px 底线**。
- 页脚固定结构：左「TIANSIGHT · 报告名」，中右「目录　术语」，右「NN / 总页数」。
- 左对齐；居中只用于封面、章节页、收尾页。
- 卡片：宣纸底、1px 金色细线、圆角 2px、无阴影；同一行卡片等高；卡片不能只有标题。
- 照片只放在独立一栏（封面右栏 688px、章节页右栏），不压在正文下面。
- 序号用中文数字加金色细圈（一 二 三 四 五），不用阿拉伯数字实心圆。

### 3.4 数字、图表与口径

- 带数字的值用等宽字体、土金色；旁边必须有说明它含义的标签。
- 以长度编码的图（柱、条）从 0 开始；排名图按数值排序；不做 3D、双坐标轴、超过 5 项的饼图。
- 散点、矩阵、气泡可用对数或密度（非等距）尺度：图上写明尺度，刻度标真实数值；象限分界、阈值线与提示按原始数据计算，不随坐标变换移动。需要时提供等距 / 非等距两版或切换。
- 每张图上方有土金小标题（说明单位、样本与尺度），图下一行短来源标记指向附录；完整口径、公式、数据期间、生成时间、字段与限制集中在附录，讲稿可补读法。
- 能标数值就标；密集标签做避让，不重叠；长列表分栏或分页并重复表头，不缩小字号硬塞。
- 装饰图片只用官方品牌图库；不得把品牌图当作客户门店实拍。
- 与本项目目标直接相关的系列用朱红，并在图例里说明「朱红 = …」。
- 坐标数字 ≥ 24px；标签框固定宽度、不换行。

### 3.5 证据与口径标签（右上角胶囊）

胶囊统一写成「中文 + 代码」：

| 标签 | 含义 | 何时用 |
|---|---|---|
| 观测值 VAL.O | 直接读自菜单、评论、POS | 计数、占比、标价 |
| 估计值 VAL.E | 规则或模型估出，有误差 | 关键词规则标注、正负判定 |
| 模拟值 VAL.S | 按规则推算 | 标准点单组合、场景模拟 |
| 设计假设值 VAL.H | 提案设定，待测试确认 | 价格区间、时限、目标值 |
| 可信上限：假设级 / 估计级 / 观测级 | CAP H < E < O | 整页结论能撑多强 |
| 外部参照 ORG.E3 | 公开统计与行业报告 | 市场背景页 |
| 数据级 DM1–DM5 | 菜单照片 → 标价 → POS → 成本卡 → 实验 | 情境与数据盘点页 |

设计系统中的「EGA E1–E4」即方法论 v3.0 的「ORG 证据来源」，报告统一写 ORG。品牌 QA 第 5 条的「设计值」「实测值」分别对应设计假设值 VAL.H 与观测值 VAL.O，两种写法可互换，同一份报告内统一一种。

## 五、制作流程（七步）

| 步 | 产出 | 要点 |
|---|---|---|
| 1 数据盘点 | `01_数据事实与字段定义.md` | 文件是什么、时间区间、条数、全部字段含义、能下与不能下的结论；**应有清单**：门店数、每店图表、每图对应明细、品项数 |
| 2 大纲与逐页数据稿 | `02_报告大纲与逐页数据稿.md` | 每页一句结论标题 + 关键数字；方法写成白话 |
| 3 计算与对账 | `res.json` 等结果文件 + 对账表 | 所有上屏数字从结果文件读取，不手敲；行数、门店数、品项数、合计与加权率与源数据对账，差异逐条列出（见 `skills/ts-data-quality`） |
| 4 生成页面 | `templates/report-kit/tsk` | 复制 `example/starter.py`；页型函数 + 一张表管理眉题、标题、标签；`apply_terms()` 统一术语 |
| 5 渲染检查 | `bash templates/report-kit/build.sh <脚本> <目录>` | lint 0 错误；SHRINK、OVERLAP、HOVERFLOW、LOW、OUTX 全部为 0；看 `.build/shots/_sheet*.png` |
| 6 核对与验收 | 逐页数字核对 + 验收记录 | 关键数字对回结果文件与原始来源；按应有清单核对每店、每图、每份明细；验收记录分「通过 / 未通过 / 未检查」三栏，不写「全部通过」除非逐项通过 |
| 7 发布与导出 | 幻灯片 + 可跳转 PDF + 数据表 | 目录、页脚、页码引用、标签可点击跳转；书签按部分 |

## 六、出版前检查清单

> `build.sh` 自动拦截：文字重叠、一两个字的孤行、标题换行、压缩与溢出、越过 y = 920 或左右边界、小于 24px、论证页标题不以句号结尾或短标题页加了句号、应有清单中的页缺失、「我们」「您」、避用词、emoji、一页多个玄墨色块、页脚字标不双色、渲染器不支持的写法、页码引用越界、PDF 链接未解析或跳错页、朱红超过 5%。下列其余各项需人工核对。

- [ ] 论证页标题为一句结论；数据页、对比页、附录可用名词短标题；一行放下，无孤字
- [ ] 门店、图、明细、品项数量与应有清单一致；精简后无缺页、缺数据
- [ ] 行数、合计、加权率与源数据对账；差异已列出
- [ ] 散点 / 矩阵的对数或密度尺度已标明，刻度为真实数值
- [ ] 每页右上标签为「中文 + 代码」
- [ ] 所有文字 ≥ 24px；渲染检查无压缩、无重叠、无越界
- [ ] 字标双色；封面印章旁不另写「侍天」
- [ ] 团队姓名与席位头衔照抄 `guidelines/company-intro-v3.md`「团队」表
- [ ] 每个数字有单位、窗口与来源；设计值、估计值已标明
- [ ] 朱红只用于警示与重点问题；一页最多一个玄墨色块
- [ ] 无「我们」「您」，无 emoji，无避用词
- [ ] 术语全文一致，术语页定义齐全
- [ ] 页码引用（「→ 第 N 页」）由程序生成，与实际页序一致
- [ ] PDF 链接全部可解析；书签完整
- [ ] 讲稿（`<aside>`）写明口径、来源与读法
- [ ] 报告分享前在页面「分享」中设置权限；只显示已授权批次
- [ ] 验收记录列出未通过与未检查项；用工具包以外方式生成的版本只声明实际做过的检查

## 七、渲染器硬约束（幻灯片格式）

| 约束 | 做法 |
|---|---|
| 只支持封闭的 CSS 子集，无 margin、z-index、em、var() | 用 gap、padding、flex 间距 |
| gap 只能一个值；padding ≤ 256 | 行列间距相同 |
| 表格单元格不能设字体、字重 | 在 table 上设字体；用颜色强调；单元格无背景，行可设背景 |
| span 只能设颜色、粗体、斜体、下划线 | 换字号就拆成两个 p |
| 链接只保留 http(s) | 页内跳转靠工具包生成的 PDF |
| 空的无底色 div 会被丢弃 | 留白用 `flex:1` 占位或有底色的块 |
| 每页 ≤ 200 个元素，每个容器 ≤ 24 个定位子元素，嵌套 ≤ 15 层 | 大表用行而不是单元格包装 |
| 边框四边须同一样式与颜色（宽度可不同） | 顶部强调线与边框同色 |
| 超出画布的内容会被整体缩字 | 用渲染检查盯 SHRINK，宁可拆页 |
| SVG 内不能写字 | 图上文字用定位的 p |
| 中文按约 1.04 × 字号/字估宽，西文约 0.58 | 标题长度用 `fit()` 自动选字号 |

## 八、报告标准结构（可按项目增减）

1. 封面 · 目录 · 执行摘要
2. **一、数据与口径**：数据盘点、字段定义、能下与不能下的结论、方法
3. **二、现状画像**：总量与节奏、结构、严重度、趋势、分布、渠道、处理方式、产品、品牌
4. **三、聚焦目标**：与项目核心目标直接相关的区域、门店、产品、案例
5. **四、市场与对策**：外部背景、优先级、设计杠杆、阶段路线、验收看板
6. **附录**：数据期间与生成时间、字段、公式、口径、来源、范围与限制、术语、完整明细表 · 收尾页

## 九、工具包与模板怎么用

| 要做的事 | 用什么 |
|---|---|
| 看规范与样张 | `deliverables/report-template/`：仓库根目录 `python3 -m http.server` 后打开该目录翻页，或看 `report-template.pdf`；第 3–14 页为规范，第 15–39 页为样张，眉题写页型编号与函数名，讲稿写用途、容量与注意事项 |
| 起一份新报告 | 复制 `templates/report-kit/example/starter.py`，填 `configure()`、`set_order()`，按页型函数写页 |
| 照样张抄写法 | `deliverables/report-template/gen/template_deck.py` 是模板本身的源码，每种页型都有一段可复制的调用 |
| 生成、检查、导出 | `bash templates/report-kit/build.sh <deck 脚本> <输出目录> [成品.pdf]`：生成 → lint → render 检查与截图 → 拼版 → 可跳转 PDF（链接未解析或跳错页即失败） |
| 发布幻灯片 | 新建 Slides 幻灯片 → 上传用到的图片得到 `/_blob/<id>` → 写 `blobs.json` → `TSK_BLOBS=blobs.json` 重新生成到临时目录 → 以 `deck.json` 为主文件、`slides/*.html` 为附属文件发布（Slides 中路径为 `project/…`），并附上设计系统 tokens 文件 |
| 短标题、应有清单、长表分页 | `configure(label_pages=[…])` 或 `title_style='label'`；`expect(组名, 页 id)`；`table_pages()` 每页重复表头；`quadrant()` 自动编号并注明本格实际数量 |
| 改了模板 | 改 `gen/template_deck.py` 或 `tsk`，重新生成并跑 `python3 scripts/check.py`（含工具包测试与模板新鲜度检查） |

环境准备、渲染器补丁与已知限制见 `templates/report-kit/README.md`。
